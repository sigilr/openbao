# Apache ZooKeeper database plugin HTTP API

The ZooKeeper database plugin is one of the supported plugins for the
database secrets engine. Unlike the SQL-style plugins, Apache ZooKeeper has
no runtime user-management API — SASL/`digest` authentication is configured
in a server-side `jaas.conf` (or a `zoo.cfg` `digest:` entry) at ensemble
startup — so this plugin does not issue dynamic credentials. Instead it
lets OpenBao track and rotate the value of a statically-provisioned
credential; see [Static Roles](/docs/secrets/databases#static-roles) and
the [ZooKeeper database secrets engine](pathname:///docs/secrets/databases/zookeeper)
docs page for the full picture.

## Configure connection

In addition to the parameters defined by the [Database
Secrets Engine](index.mdx#configure-connection), this plugin
has a number of parameters to further configure a connection.

| Method | Path                     |
| :----- | :----------------------- |
| `POST` | `/database/config/:name` |

### Parameters

- `address` `(string: <required>)` – Specifies `host:port` for one node of
  the ZooKeeper ensemble. Used only to perform the reachability check
  (ZooKeeper's 4-letter `ruok` command) during `Initialize` /
  `VerifyConnection` — the plugin does not maintain a connected client.

- `username` `(string: "")` – Specifies the digest username carried for
  static-role tracking. Not sent as part of the `ruok` reachability check.

- `password` `(string: "")` – Specifies the digest password corresponding to
  `username`, carried for static-role tracking. Not sent as part of the
  `ruok` reachability check.

This plugin does not accept `username_template` — ZooKeeper credentials are
tracked under the literal `username` configured on a static role, and this
plugin does not generate its own usernames. It also does not accept any
TLS-related parameters; the reachability check is a plain TCP connection.

### Sample payload

```json
{
  "plugin_name": "zookeeper-database-plugin",
  "allowed_roles": "app",
  "address": "zookeeper.example.com:2181"
}
```

### Sample request

```shell-session
$ curl \
    --header "X-Vault-Token: ..." \
    --request POST \
    --data @payload.json \
    http://127.0.0.1:8200/v1/database/config/zk
```

## Statements

ZooKeeper has no dynamic-user statement language usable by this plugin —
it has no runtime user-management API at all, and znode ACLs are tied to
existing digest principals rather than driven by statement-style input. As
a result the plugin does not read or use `creation_statements`,
`revocation_statements`, `rollback_statements`, or
`root_rotation_statements` at all; any value supplied for these fields is
accepted by the database secrets engine framework but ignored.

- Dynamic roles (`bao write database/roles/:name` followed by
  `bao read database/creds/:name`) are **not supported**. Creating a
  dynamic role succeeds, but reading credentials from it always fails with:

  ```text
  dynamic credentials are not supported by ZooKeeper (SASL/digest
  principals are loaded from jaas.conf/zoo.cfg at startup); use
  static-roles to track a manually-provisioned credential, or run a
  sidecar that updates the server config on UpdateUser
  ```

- Static roles are the supported credential-tracking mechanism. Configure
  one with a `username` that already exists in `jaas.conf` / `zoo.cfg`, and
  a `rotation_period`:

  ```shell-session
  $ bao write database/static-roles/app \
      db_name=zk \
      username=app \
      rotation_period=24h
  ```

  On each rotation OpenBao generates a new password and stores it — it
  does not push the value to the ZooKeeper ensemble. An external system
  must apply the same password to the `jaas.conf` / `zoo.cfg` digest entry
  (and any znode ACLs referencing it) backing that credential, typically
  followed by a rolling restart, to keep it in sync.

- Root credential rotation (`bao write -force database/rotate-root/:name`)
  behaves the same way: OpenBao generates and stores a new root
  `username`/`password` pair in the connection configuration without
  contacting the ensemble.
