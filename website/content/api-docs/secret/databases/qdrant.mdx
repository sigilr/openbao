# Qdrant database plugin HTTP API

The Qdrant database plugin is one of the supported plugins for the database
secrets engine. Unlike the SQL-style plugins, Qdrant has no runtime
key-management API, so this plugin does not issue dynamic credentials.
Instead it lets OpenBao track and rotate the value of a
statically-provisioned API key; see [Static
Roles](/docs/secrets/databases#static-roles) and the [Qdrant database
secrets engine](pathname:///docs/secrets/databases/qdrant) docs page for the
full picture.

## Configure connection

In addition to the parameters defined by the [Database
Secrets Engine](index.mdx#configure-connection), this plugin
has a number of parameters to further configure a connection.

| Method | Path                     |
| :----- | :----------------------- |
| `POST` | `/database/config/:name` |

### Parameters

- `url` `(string: <required>)` – Specifies the `http(s)://host:port` of the
  Qdrant server OpenBao connects to for its reachability check.

- `api_key` `(string: "")` – Specifies the API key sent as the `api-key`
  header when verifying the connection. This is the value tracked and
  rotated through static roles; it is not pushed to the server by this
  plugin.

- `ca_cert` `(string: "")` – Specifies a PEM-encoded CA certificate (or
  bundle) used to validate the server's TLS certificate.

- `ca_path` `(string: "")` – Specifies a filesystem path to a PEM-encoded
  CA certificate (or bundle) used to validate the server's TLS certificate.

- `client_cert` `(string: "")` – Specifies a PEM-encoded client certificate
  to present for mTLS. Must be set together with `client_key`.

- `client_key` `(string: "")` – Specifies the PEM-encoded private key
  corresponding to `client_cert`. Must be set together with `client_cert`.

- `insecure` `(bool: false)` – Skips verification of the server's TLS
  certificate when connecting. Intended for development only.

This plugin does not accept `username_template` — Qdrant API keys are
tracked under the literal `username` configured on a static role, and this
plugin does not generate its own usernames or send them to the server.

### Sample payload

```json
{
  "plugin_name": "qdrant-database-plugin",
  "allowed_roles": "app",
  "url": "https://qdrant.example.com:6333",
  "api_key": "topsecret"
}
```

### Sample request

```shell-session
$ curl \
    --header "X-Vault-Token: ..." \
    --request POST \
    --data @payload.json \
    http://127.0.0.1:8200/v1/database/config/qdrant
```

## Statements

Qdrant has no statement language of its own — there is no SQL-style
`CREATE USER`/`GRANT` and no runtime key-management call this plugin could
send. As a result the plugin does not read or use `creation_statements`,
`revocation_statements`, `rollback_statements`, or
`root_rotation_statements` at all; any value supplied for these fields is
accepted by the database secrets engine framework but ignored.

- Dynamic roles (`bao write database/roles/:name` followed by
  `bao read database/creds/:name`) are **not supported**. Creating a
  dynamic role succeeds, but reading credentials from it always fails with:

  ```text
  dynamic credentials are not supported by Qdrant (the API key is loaded
  from QDRANT__SERVICE__API_KEY at startup); use static-roles to track a
  manually-provisioned API key, or run a sidecar that updates the server
  config on UpdateUser
  ```

- Static roles are the supported credential-tracking mechanism. Configure
  one with a `username` naming the tracked key, and a `rotation_period`:

  ```shell-session
  $ bao write database/static-roles/app \
      db_name=qdrant \
      username=app \
      rotation_period=24h
  ```

  On each rotation OpenBao generates a new key and stores it — it does not
  push the value to the Qdrant server. An external system must apply the
  same value to the server's `QDRANT__SERVICE__API_KEY` configuration (and
  restart or reload the process) to keep it in sync.

- Root credential rotation (`bao write -force database/rotate-root/:name`)
  behaves the same way: OpenBao generates and stores a new root
  `username`/`api_key` pair in the connection configuration without
  contacting the server.
