# Memcached database plugin HTTP API

The Memcached database plugin is one of the supported plugins for the
database secrets engine. Unlike the SQL-style plugins, Memcached has no
runtime user-management API, so this plugin does not issue dynamic
credentials. Instead it lets OpenBao track and rotate the value of a
statically-provisioned SASL credential; see [Static
Roles](/docs/secrets/databases#static-roles) and the [Memcached database
secrets engine](pathname:///docs/secrets/databases/memcached) docs page for
the full picture.

## Configure connection

In addition to the parameters defined by the [Database
Secrets Engine](index.mdx#configure-connection), this plugin
has a number of parameters to further configure a connection.

| Method | Path                     |
| :----- | :----------------------- |
| `POST` | `/database/config/:name` |

### Parameters

- `address` `(string: <required>)` – Specifies the `host:port` of the
  Memcached server OpenBao connects to for its reachability check.

- `username` `(string: "")` – Specifies a username used when verifying the
  connection. Not currently sent as part of a SASL handshake by the
  reachability check performed on `Initialize`/`VerifyConnection`.

- `password` `(string: "")` – Specifies a password corresponding to
  `username`. Not currently sent as part of a SASL handshake by the
  reachability check performed on `Initialize`/`VerifyConnection`.

- `use_tls` `(bool: false)` – Specifies whether to use TLS when connecting to
  the server. Automatically implied if `tls_ca`, `tls_ca_path`, or
  `client_cert` is set.

- `tls_ca` `(string: "")` – Specifies a PEM-encoded CA certificate (or
  bundle) used to validate the server's TLS certificate.

- `tls_ca_path` `(string: "")` – Specifies a filesystem path to a PEM-encoded
  CA certificate (or bundle) used to validate the server's TLS certificate.

- `client_cert` `(string: "")` – Specifies a PEM-encoded client certificate
  to present for mTLS. Must be set together with `client_key`.

- `client_key` `(string: "")` – Specifies the PEM-encoded private key
  corresponding to `client_cert`. Must be set together with `client_cert`.

- `insecure` `(bool: false)` – Skips verification of the server's TLS
  certificate when connecting. Intended for development only.

This plugin does not accept `username_template` — Memcached credentials are
tracked under the literal `username` configured on a static role, and this
plugin does not generate its own usernames.

### Sample payload

```json
{
  "plugin_name": "memcached-database-plugin",
  "allowed_roles": "app",
  "address": "memcached.example.com:11211"
}
```

### Sample request

```shell-session
$ curl \
    --header "X-Vault-Token: ..." \
    --request POST \
    --data @payload.json \
    http://127.0.0.1:8200/v1/database/config/memcached
```

## Statements

Memcached has no statement language of its own — there is no SQL-style
`CREATE USER`/`GRANT` and no Redis-style `ACL SETUSER` command this plugin
could send. As a result the plugin does not read or use
`creation_statements`, `revocation_statements`, `rollback_statements`, or
`root_rotation_statements` at all; any value supplied for these fields is
accepted by the database secrets engine framework but ignored.

- Dynamic roles (`bao write database/roles/:name` followed by
  `bao read database/creds/:name`) are **not supported**. Creating a
  dynamic role succeeds, but reading credentials from it always fails with:

  ```text
  dynamic credentials are not supported by Memcached (no runtime
  user-management API); use static-roles to track a manually-provisioned
  SASL credential, or run a sidecar that updates the auth file on UpdateUser
  ```

- Static roles are the supported credential-tracking mechanism. Configure
  one with a `username` that already exists in the Memcached server's SASL
  auth file, and a `rotation_period`:

  ```shell-session
  $ bao write database/static-roles/app \
      db_name=memcached \
      username=app \
      rotation_period=24h
  ```

  On each rotation OpenBao generates a new password and stores it — it does
  not push the value to the Memcached server. An external system must apply
  the same password to the server's SASL auth file to keep it in sync.

- Root credential rotation (`bao write -force database/rotate-root/:name`)
  behaves the same way: OpenBao generates and stores a new root
  `username`/`password` pair in the connection configuration without
  contacting the server.
