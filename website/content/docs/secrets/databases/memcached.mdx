# Memcached database secrets engine

Memcached is one of the supported plugins for the database secrets engine, but
it works differently from the SQL-style plugins. Memcached has **no runtime
user-management API** — SASL credentials for a Memcached server are loaded
from a static auth file at process startup, and there is no protocol
equivalent to a SQL `CREATE USER`/`GRANT` or a Redis `ACL SETUSER` that this
plugin could call at request time.

Instead, `memcached-database-plugin` lets OpenBao be the source of truth for
a SASL credential's value and rotation schedule, using [Static
Roles](index.mdx#static-roles) as the primary supported workflow:

- `Initialize` (and `VerifyConnection`) open a TCP (optionally TLS)
  connection to the configured `address` and issue a `stats` command to
  confirm the server is reachable. This is a reachability check, not a SASL
  handshake.
- Dynamic credentials (`bao read database/creds/...`) are **not supported**.
  `NewUser` always returns an explicit error telling the operator to use
  static roles or external configuration management instead.
- Static-role rotation (`UpdateUser`) does not contact the Memcached server
  at all. It validates the request and returns success so that OpenBao
  tracks the new password and emits the usual audit events, but applying
  that password to the server's SASL auth file is left to an external
  system — a sidecar or configuration-management tool that watches OpenBao
  and rewrites the file — which is out of scope for this plugin.
- `DeleteUser` is likewise a no-op against the server.

See the [database secrets engine](index.mdx) docs for more information about
setting up the database secrets engine.

## Capabilities

| Plugin Name                | Root Credential Rotation | Dynamic Roles | Static Roles | Username Customization |
| --------------------------- | ------------------------- | --------------- | --------------- | ------------------------- |
| `memcached-database-plugin` | Yes                      | No             | Yes           | No                      |

Both "Root Credential Rotation" and "Static Roles" here are OpenBao-side
bookkeeping only: `bao write -force database/rotate-root/<name>` and
static-role rotation both succeed and update the password OpenBao tracks,
but neither pushes the new password to the Memcached server. An operator or
sidecar must apply the same value to the server's SASL auth file out of
band to keep it in sync. `memcached-database-plugin` does not support
`username_template` — usernames are the literal value configured on the
static role.

## Setup

1.  Enable the database secrets engine if it is not already enabled:

    ```shell-session
    $ bao secrets enable database
    Success! Enabled the database secrets engine at: database/
    ```

    By default, the secrets engine will enable at the name of the engine. To
    enable the secrets engine at a different path, use the `-path` argument.

1.  Configure OpenBao with the proper plugin and connection information:

    ```shell-session
    $ bao write database/config/memcached \
        plugin_name="memcached-database-plugin" \
        address="memcached.example.com:11211" \
        allowed_roles="app"
    Success! Data written to: database/config/memcached
    ```

1.  Configure a static role that maps a name in OpenBao to a
    manually-provisioned Memcached SASL username, and a rotation period for
    OpenBao to generate and track a new password on:

    ```shell-session
    $ bao write database/static-roles/app \
        db_name="memcached" \
        username="app" \
        rotation_period="24h"
    Success! Data written to: database/static-roles/app
    ```

    Attempting to create a dynamic role and read `database/creds/<role>`
    against this plugin fails with an explicit
    "dynamic credentials are not supported by Memcached" error — use static
    roles as shown above instead.

## Usage

After the secrets engine is configured and a user/machine has an OpenBao token
with the proper permission, it can read the current static credential.

1.  Read the tracked password from the `/static-creds` endpoint with the name
    of the role:

    ```shell-session
    $ bao read database/static-creds/app
    Key                    Value
    ---                    -----
    last_vault_rotation    2026-08-07T09:00:00.000000000Z
    password               SsnoaA-8Tv4t34f41baD
    rotation_period        24h
    ttl                    23h59m12s
    username               app
    ```

    Update the Memcached server's SASL auth file with this password out of
    band (for example, from a sidecar or configuration-management run) to
    keep the server in sync with OpenBao.
